# Expressions, Declarations & Functions — Programming Languages Part A

## What does "evaluates to a value" mean?

- **Evaluate** = to run/process a piece of code
- **"Evaluates to a value"** = after processing finishes, the end result is a value
- This can mean two different things:
    - **Computing something new** — e.g. `5 + 3` evaluates to `8` (a new value is calculated)
    - **Looking up something that already exists** — e.g. given `int x = 4;`, the line `x` evaluates to `4` (no new value is made, it just retrieves the existing binding)
- We use **"evaluates to"** instead of "creates" or "returns" because it covers BOTH cases above.

---

## Expression

A piece of code that **evaluates to a value**.

**Examples (with full context):**

```
4           // evaluates to 4 (self-evaluating, needs no context)
5 + 3       // evaluates to 8 (computes a new value)

int x = 4;  // (declaration — binds x to 4, see below)
x;          // evaluates to 4 (looks up existing binding — this IS an expression)
x + 3;      // evaluates to 7 (uses the looked-up value in a computation)
```

**Note on context:**

- Some expressions are **self-evaluating** — they don't need any existing binding (e.g. `4`, `true`)
- Other expressions need an **environment** (the set of current name-to-value bindings) to evaluate — e.g. `x` needs to know that `x` was bound to `4` first

**How to test if something is an expression:**

1. Does it evaluate to a value?
2. Can you nest it inside another operation? → e.g. `(5 + 3) + 2`
3. Can you assign it to something? → e.g. `int y = 5 + 3;` / `val x = ___`
4. Can you pass it as an argument? → e.g. `print(x + 3);`

If yes to these, it's an expression.

---

## Declaration / Statement

A piece of code that does **NOT** evaluate to a value — running it does not produce a usable value.

- **Declaration**: introduces a new name (variable, function, etc.) into the program
    - Example: `int x = 4;` — introduces the name `x`, binds it to `4`
    - You cannot use the "result" of this line, because there is no value produced — only a new binding is set up
- **Other statements**: don't introduce a new name, and also don't evaluate to a value
    - Example: `x = 3;` — re-binds the existing `x` to a new value (3), but the line itself has no usable result
    - Example: `if (x > 2) { ... }` — controls what runs next, but has no usable result

**How to test if something is a declaration/statement (not an expression):**

1. Can you use its "result" elsewhere? → No → `int y = (int x = 4);` is invalid
2. Can you nest it inside another operation? → No → `2 * (int x = 2)` is invalid

## Key Rule: Nesting Declarations

❌ **Cannot nest a `dec` directly inside another `dec`'s right-hand side**

- `int y = (int x = 3);` — invalid. `int x = 3` produces no value, so there is nothing to assign to `y`.
- `2 * (int x = 2)` — invalid, same reason: no value to multiply.

✅ **ML's `let...in...end` construct — a bridge between declaration and expression**

- **"Bridge" here means:** a language feature that connects two things that normally cannot connect directly. In this case, it takes a `dec` (which cannot be used as an `exp`) and wraps it so the whole thing becomes a valid `exp`.
- How it works:
    1. The `dec` part (e.g. `val x = 2`) sets up a binding
    2. The `exp` part after `in` (e.g. `x`) is evaluated _using_ that binding
    3. **The value of the whole `let...in...end` construct = the value of that inner `exp`**

**Example (full context):**

```sml
val y =
    let
        val x = 2   (* dec: binds x to 2 *)
    in
        x           (* exp: evaluates to 2, using the binding above *)
    end
(* the whole let...in...end evaluates to 2 *)
(* so val y = ... is valid: y is bound to 2 *)
```

**Two-step composition (the general pattern):**

1. `dec` nested inside `let...in...end` → produces an `exp`
2. That resulting `exp` nested inside another `dec`'s right-hand side → now valid!

This is a general programming-language-design pattern: a construct that takes one category of thing (here, a `dec`) and produces a different category (here, an `exp`), so it can be used where the original could not.

**Also important:** since `let...in...end` produces an `exp`, it can be used ANYWHERE an expression is expected — not only inside another `dec`. For example:

```sml
let val x = 4 in x + 3 end
```

This whole thing evaluates to `7`, and can be used just like `4` or `x + 3` — passed to functions, combined with other operators, etc.

## Ternary / conditional expression (Java-style example)

```java
(z > 0) ? z - 1 : z + 1
```

- If `z > 0` is true → evaluates to `z - 1`
- If `z > 0` is false → evaluates to `z + 1`
- Either way, the whole thing evaluates to **one value** — so it's an expression, just like `x + 3`.

**Can be nested / assigned / passed, same as any expression:**

```java
int result = ((z > 0) ? z - 1 : z + 1) + 10;   // nested in another operation
print((z > 0) ? z - 1 : z + 1);                 // passed as an argument
int y = (z > 0) ? z - 1 : z + 1;                // assigned
```

## Nested `let` expressions (SML)

```sml
let
    val x = 5
in
    let
        val y = 3
    in
        x + y
    end
end
```

Work from the **inside out**:

1. Outer `let` binds `x = 5`
2. Inner `let` binds `y = 3` — and can still "see" `x` from the outer binding (this is called **scope**)
3. Innermost expression `x + y` uses both bindings → `5 + 3 = 8`
4. Inner `let...in...end` evaluates to `8`
5. That becomes the body of the outer `let`, so the **whole thing evaluates to `8`**

## Functions as values (first-class functions)

```sml
fn x => x + 1
```

- This is SML syntax for an (anonymous) **function**: "take input `x`, compute `x + 1`"
- **Key idea: in SML, a function itself is a value** — just like `4` is a value or `true` is a value.
- Because it's a value, `fn x => x + 1` **is an expression**: it evaluates to a function value.

**Proof by testing (run in SML REPL):**

```sml
fn x => x + 1;              (* works standalone — like typing 4; *)
val f = fn x => x + 1;      (* works — same as val x = 4; *)
```

Both work, confirming `fn x => x + 1` behaves like any other expression: it can stand alone, and it can sit on the right-hand side of a `val` declaration.

**General theory — "first-class functions":**
Languages where functions can be assigned to variables, passed as arguments, and returned from other functions are said to have **first-class functions**.

- Languages with first-class functions: SML/ML, Python, JavaScript, modern Java (lambdas)
- Languages historically without: older Java (pre-lambdas), C (only function pointers as a workaround)

ML/Part A is built entirely around this idea — functions are treated exactly like any other value. This is a core theme of the course.

## Function application

```sml
(fn x => x + 1) 5
```

This is called **function application**: a function placed right next to an argument.

**Evaluation steps:**

1. `fn x => x + 1` evaluates to a function value (a "recipe": take input `x`, compute `x + 1`)
2. `5` evaluates to the value `5`
3. **Apply** the function to the argument: substitute `x` with `5` in the function body → `5 + 1`
4. Evaluate `5 + 1` → `6`

Result (confirmed in REPL): `val it = 6 : int`

**General pattern:** `<function> <argument>` → apply the function to the argument → get a result.

**`(fn x => x + 1) 5` is itself an expression** — it evaluates to `6`, so like everything else in ML, it can be nested, passed around, and combined with other expressions.
