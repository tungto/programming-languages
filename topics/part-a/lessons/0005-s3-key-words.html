Key words for functions and closures

The words Section 3 uses for passing functions around, in plain English. The PDF says lexical scope is "the most subtle and important concept in the entire course". This is a word list, not the full lesson.

Source · section3sum.pdfTime · 25-35 minRecommended · the section summary, after this page

1How to use this page

Cover the meaning and say each word in your own words first. Then open the card. Each card has: a plain meaning, the smallest example, what it is not, and a picture to remember it.

Words in bold inside a meaning are the part to remember. Page links go to the exact page in the section summary.

Why words come first

The summary explains each idea using other key words. If one word is fuzzy, the whole sentence is fuzzy. Fixing the words fixes most of the confusion.

2Functions as values

Three words people mix up; the PDF says they are different ideas.

Try first: say one sentence for each word before reading the cards

First-class function, Higher-order function, Anonymous function (fn), Unnecessary function wrapping, Parametric polymorphism (generics), Map / filter / fold, Iterator, Predicate, Client / implementer

First-class function

A function you can use like any value: pass it, return it, store it in a tuple.

val fs = [fn x => x + 1, fn x => x * 2]

summary p.1

Higher-order function

A function that takes or returns a function.

fun n_times (f, n, x) = ...

summary p.1

Anonymous function (fn)

A function with no name, written where it is used.

fn x => 3 * x

Not the same asCannot be recursive (it has no name to call).

Picture itJS arrow function x => 3 * x.

summary p.4

Unnecessary function wrapping

Writing fn x => f x when f alone is the same thing.

n_times (tl, 2, xs)   (* not fn y => tl y *)

Picture itLike if x then true else false instead of x.

summary p.4

Parametric polymorphism (generics)

Types with 'a so one function works for any type. Separate idea from higher-order.

('a -> 'a) * int * 'a -> 'a

Picture itJava/TS generics <T>.

summary p.3

Map / filter / fold

Three iterators. map changes each element; filter keeps some; fold combines all into one answer.

map (fn x => x + 1, xs)
filter (fn x => x > 0, xs)
fold (fn (acc, x) => acc + x, 0, xs)

Not the same asfold is also called reduce.

Picture itJS .map, .filter, .reduce.

summary p.5

Iterator

A function that walks over a data structure and calls your function on the pieces.

summary p.9

Predicate

A function that returns bool. filter takes one.

fn x => x mod 2 = 0

summary p.5

Client / implementer

Implementer writes a function (e.g. map). Client uses it (passes its own f).

summary p.5

3Scope and closures

The core of the section. Read each one slowly.

Try first: say one sentence for each word before reading the cards

Lexical scope, Dynamic scope, Free variable, Closure, Closed, Recomputation

Lexical scope

A function body uses the environment where the function was defined.

val x = 1
fun f y = x + y
val x = 2
val z = f 3     (* 4, uses x = 1 *)

Not the same asDynamic scope: uses the environment where it is called (would give 5).

Picture itA letter written at home still talks about home, wherever it is read.

summary p.7

Dynamic scope

Using the caller's environment. ML does not do this. Exception handling is the one thing that behaves like it.

summary p.7

Free variable

A variable used in a function but not defined inside it. Above, x is free in f.

fun f y = x + y   (* x is free *)

Not the same asBound variable: an argument or local (y).

summary p.7

Closure

A function value = code + the environment where it was defined. You can only call it; you cannot read the parts.

fun adder n = fn x => x + n
val add5 = adder 5   (* code: x + n,  env: n = 5 *)

Picture itA backpack: the code carries the values it needs.

summary p.7

Closed

A closure is "closed" because its environment gives a value to every free variable.

summary p.7

Recomputation

Work inside fn runs on every call; work in a let outside it runs once.

let val i = String.size s in filter (fn x => String.size x < i, xs) end

summary p.9

4Closure idioms

Named patterns that rely on closures.

Try first: say one sentence for each word before reading the cards

Composition (o), Pipeline (|>), Currying, Partial application, -> associates to the right, Value restriction, Reference (ref, !, :=), Side effect, Callback / register, Abstract data type (ADT)

Composition (o)

Make one function from two: (f o g) x = f (g x). Runs right to left.

val sqrt_of_abs = Math.sqrt o Real.fromInt o abs

summary p.11

Pipeline (|>)

Like composition but left to right: x |> f = f x.

i |> abs |> Real.fromInt |> Math.sqrt

Picture itUnix pipe |.

summary p.11

Currying

A "multi-argument" function that takes one argument and returns a function for the next.

fun add x y = x + y   (* int -> int -> int *)

Not the same asTupling: fun add (x, y).

summary p.12

Partial application

Calling a curried function with fewer arguments to get a new function.

val add1 = add 1   (* int -> int *)

Picture itPre-filling part of a form.

summary p.12

-> associates to the right

t1 -> t2 -> t3 means t1 -> (t2 -> t3). Calls go the other way: f a b is (f a) b.

summary p.6

Value restriction

A val binding gets a polymorphic type only if the right side is a value or variable. Fix: write a fun.

val pairIt = List.map (fn x => (x, x))   (* warning *)
fun pairIt xs = List.map (fn x => (x, x)) xs   (* ok *)

summary p.14

Reference (ref, !, :=)

A mutable box. ref e makes it, !r reads, r := e writes.

val r = ref 0
val _ = r := !r + 1

Not the same as! is not "not".

summary p.15

Side effect

Anything a call does besides returning a value: mutation, printing, raising.

summary p.15

Callback / register

A function you give to a library to be called later on an event. Registering = handing it over.

onKeyEvent (fn k => ...)

Picture itJS addEventListener.

summary p.15

Abstract data type (ADT)

A type used only through its functions; its insides are hidden.

summary p.16

5One closure, made and called

Follow where each name is looked up. The argument uses the call-site environment; the body uses the saved one.

CodeWhat changesWhy
val x = 1env: x → 1
fun f y = x + yf → closure { code: x + y, env: x → 1 }saves env now
val x = 2env: x → 2 (shadows)f's saved env unchanged
val z = f (x + 1)argument: x + 1 = 3 (current env)body: x + y in saved env + y → 3 = 4
Try first: Under dynamic scope, what would z be?

5: the body would use the current x = 2.

Try first: What is a closure made of?

The function's code and the environment where it was defined.
