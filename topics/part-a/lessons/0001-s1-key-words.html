Key words for ML basics

The words Section 1 uses on every page, in plain English, each with a tiny example. Read this before the study guide. It is a word list, not a full lesson on ML.

Source · section1sum.pdfTime · 25-35 minRecommended · the section summary, after this page

1How to use this page

Cover the meaning and say each word in your own words first. Then open the card. Each card has: a plain meaning, the smallest example, what it is not, and a picture to remember it.

Words in bold inside a meaning are the part to remember. Page links go to the exact page in the section summary.

Why words come first

The summary explains each idea using other key words. If one word is fuzzy, the whole sentence is fuzzy. Fixing the words fixes most of the confusion.

2The pieces of a program

The PDF says: "pay extremely careful attention to the words." These five words are the base for everything else.

Try first: say one sentence for each word before reading the cards

Expression, Value, Binding (declaration), Variable, Keyword, Construct (noun), Subexpression

Expression

A piece of code that produces a value. In ML almost everything is an expression: 3, x + 1, if ... then ... else ..., a function call.

8 + 9      (* an expression; it produces 17 *)

Not the same asA statement (in Java/JS) does an action and produces nothing. ML has no statements.

Picture itA question that always has an answer.

summary p.2

Value

An expression that is already finished: there is nothing left to compute. 17 is a value; 8 + 9 is not (yet).

17   true   (3, 4)   []

Not the same asAll values are expressions. Not all expressions are values.

Picture itThe answer, not the question.

summary p.2

Binding (declaration)

A line that gives a name to something and adds that name to the environment. An ML program is just a list of bindings.

val x = 34           (* variable binding *)
fun double y = y + y  (* function binding *)

Not the same as"Declaration" is the general word other courses use; this course says "binding". Not an assignment: a binding never changes.

Picture itWriting a name on a label and sticking it on a box. You never re-write the label; you can only add a new label.

summary p.2

Variable

A name that refers to a value. In ML a variable is bound once; it cannot be changed later.

val x = 34   (* x is the variable *)

Not the same asNot a "box you can update" like let x in JS. More like const.

summary p.2

Keyword

A word reserved by the language with a fixed meaning. You cannot use it as a variable name.

val  fun  if  then  else  let  in  end  case  of

summary p.2

Construct (noun)

Any kind of language feature: if-then-else is a construct, let is a construct. Note: here it is a noun (CON-struct), not the verb "to construct".

Not the same asNot "constructor" (Section 2: a datatype tag).

Picture itA type of LEGO piece.

summary p.3

Subexpression

An expression inside a bigger expression.

if y > 0 then 0 else x + 1
(* y > 0,  0,  x + 1  are subexpressions *)

summary p.2

3How code is checked and run

Every construct has three rules: syntax, type-check, evaluate. These words name the three.

Try first: say one sentence for each word before reading the cards

Syntax, Semantics, Type, Type-check, Evaluate, Compile time vs run time

Syntax

How you write it: the spelling and order of the symbols.

if e1 then e2 else e3   (* syntax of a conditional *)

Not the same asNot the meaning. Correct syntax can still fail to type-check.

Picture itGrammar of a sentence.

summary p.2

Semantics

What it means: how it type-checks and how it evaluates.

Not the same asSyntax = form; semantics = meaning.

Picture itThe meaning of a sentence.

summary p.2

Type

A label that says what kind of value an expression will produce.

int   bool   int * bool   int list   int -> int

summary p.2

Type-check

Checking, before the program runs, that every expression is used with the right types. If it fails, the program never runs.

val y = true + 1   (* rejected: + needs int, true is bool *)

Not the same asNot running the code. No values are computed yet.

Picture itA spelling check before you send the email.

summary p.2

Evaluate

Run an expression to get its value. "e evaluates to v" = running e gives v.

x + 1   (* with x = 34, evaluates to 35 *)

Not the same asNot type-checking. Evaluate happens after, at run time.

Picture itDoing the math.

summary p.2

Compile time vs run time

Compile time = before the program runs (type-checking happens here). Run time = while it runs (evaluation happens here).

Not the same as"Static" ≈ compile time. "Dynamic" ≈ run time.

summary p.2

4Environments

These are the hardest words in Section 1 and the most important: closures (Section 3) are built on them.

Try first: say one sentence for each word before reading the cards

Environment, Static environment, Context, Dynamic environment, Look up, Scope, Shadowing, Immutable

Environment

A table from names to something. It grows by one row for each binding. Alone, "environment" usually means the dynamic environment.

Not the same asNot your OS / shell environment variables.

Picture itA dictionary that is read top-down.

summary p.2

Static environment

The table names → types. Used to type-check. "Static" = known before running.

val x = 34   (* static env gets  x : int *)

Not the same asNot the Java keyword static (the PDF says the link is "too tenuous").

Picture itThe guest list with each guest's job title.

summary p.2

Context

Another word for static environment. Same idea, different name.

Not the same asIn everyday English "context" is vague; here it means exactly names → types.

summary p.2

Dynamic environment

The table names → values. Used to evaluate. "Dynamic" = while running.

val x = 34   (* dynamic env gets  x --> 34 *)

Not the same asNot "dynamic typing" (Racket). ML is statically typed but still has a dynamic environment.

Picture itThe guest list with each guest's phone number.

summary p.2

Look up

Find a name in an environment and get its type (static) or value (dynamic).

x + 1   (* look up x, then add *)

summary p.3

Scope

Where a binding can be used. A let binding's scope is the later bindings in that let and its body.

let val a = 1 in a + 1 end   (* a's scope ends at end *)

Picture itThe rooms where a name tag is valid.

summary p.8

Shadowing

A new binding with an old name. Later code sees the new one; earlier code still sees the old one. Nothing is changed.

val a = 1
val a = 2   (* shadows; the first a still exists for older code *)

Not the same asNot mutation/assignment.

Picture itCovering an old poster with a new one. The old poster is still underneath.

summary p.4

Immutable

Cannot be changed after it is made. ML bindings, tuples and lists are immutable.

Not the same asMutable = can change (JS arrays, Java objects).

Picture itPrinted text vs a whiteboard.

summary p.4

5Functions and data

Words for calling functions and building data.

Try first: say one sentence for each word before reading the cards

Function binding, Argument / parameter, Body, Function call, Recursion / base case, Compound data, Tuple / pair, Cons (::), Option, Exception (raise), Alias, REPL, Idiom

Function binding

A binding that makes a function: name, arguments, body.

fun pow (x : int, y : int) = if y = 0 then 1 else x * pow (x, y - 1)

summary p.4

Argument / parameter

Parameter = the name in the definition (x, y). Argument = the value passed in a call (4, 3). The PDF often says "argument" for both.

fun cube (x : int) = pow (x, 3)   (* x = parameter *)
val ans = cube 4                   (* 4 = argument *)

summary p.4

Body

The expression after = in a function. Its value is the function's result. There is no return.

fun double x = x + x   (* body: x + x *)

summary p.4

Function call

An expression that runs a function with arguments.

pow (2, 3)

summary p.5

Recursion / base case

A function that calls itself. The base case is the input where it stops (often [] or 0).

fun sum_list xs = if null xs then 0 else hd xs + sum_list (tl xs)

Picture itRussian dolls: open until the smallest one.

summary p.7

Compound data

Data built from smaller data: tuples, lists, options.

(7, (true, 9))

Not the same asBase types: int, bool, unit.

summary p.5

Tuple / pair

A fixed number of parts that may have different types. A pair is a 2-tuple.

(1, true)   : int * bool

Not the same asNot a list (a list can grow, all same type).

summary p.5

Cons (::)

Put one element in front of a list. Read e1 :: e2 as "e1 consed onto e2".

1 :: [2, 3]   (* [1,2,3] *)

summary p.6

Option

A value that holds 0 or 1 thing: NONE or SOME v.

SOME 5 : int option     NONE : 'a option

Not the same asNot null. You must check which one you have.

Picture itA box that may be empty.

summary p.10

Exception (raise)

A run-time error signal. hd [] raises one.

hd []   (* raises an exception *)

summary p.6

Alias

Two names for the same data in memory. With no mutation, you cannot tell an alias from a copy.

val x = (3, 4)
val y = sort_pair x   (* y may be an alias of x; it does not matter *)

Not the same asCopy = a separate second piece of data.

Picture itTwo nicknames for one person.

summary p.12

REPL

Read-Eval-Print Loop: the interactive prompt where you type bindings. use "f.sml"; loads a file into it.

summary p.3

Idiom

A common, good way to use language features.

Not the same asNot a feature itself.

Picture itA common phrase in English.

summary p.14

6One program, two environments

Watch both tables grow, one row per binding. This is what "static environment" and "dynamic environment" mean in practice.

CodeWhat changesWhy
val x = 34x : intx → 34
val y = 17…, y : int…, y → 17
val z = (x + y) + (y + 2)…, z : int…, z → 70
val q = z + 1…, q : int…, q → 71
val x = 0…, x : int (new)…, x → 0 (shadows 34)
Try first: Which environment does true + 1 fail in, and when?

The static environment, at compile time (type-check). It never reaches evaluation.

Try first: After the last line, what does an older function that used x see?

34. Its environment was saved when it was defined; the new x shadows only for later code.
