Part I

Type inference

How ML finds every type without annotations.

1What type inference is

Type inference gives every binding a type that the checker could have accepted with annotations; it is a separate question from static vs dynamic typing. [summary p.1]

LanguageStatic?Inferred?
MLyesyes, almost fully
Java / Cyespartly (local var, auto)
Racket / JSno (dynamic)n/a

Lecture code: 66_what_is_type_inference.sml

2How ML does it

Bindings are checked in order; for each one, collect constraints from how variables are used, solve them, and turn leftover unknowns into 'a, 'b. [summary p.2]

fun f x =               (* f : T1 -> T2,  x : T1 *)
    let val (y, z) = x     (* T1 = T3 * T4 *)
    in abs y + z end       (* abs : int -> int, so T3 = int; + gives T4 = int, T2 = int *)
(* f : int * int -> int *)
Try first: Infer the type of fun g (f, x) = f (f x).

Hint: write T1 for f, T2 for x, then add one equation per use

('a -> 'a) * 'a -> 'a: f's result is fed back into f, so its input and output types must match.

Lecture code: 67_ml_type_inference.sml, 68_type_inference_examples.sml, 69_polymorphic_examples.sml

3Value restriction and harder cases

A val binding gets a polymorphic type only if its expression is a value or a variable; this blocks a 'a list ref that could hold both strings and ints. [summary p.6]

val r = ref NONE          (* would be 'a option ref: unsafe *)
val _ = r := SOME "hi"
val i = 1 + valOf (!r)     (* the restriction rejects this program *)
Easy to get wrong: the restriction is only about refs

The checker cannot tell which calls make refs, so it restricts all non-value val bindings, including val f = map g.

Lecture code: 70_other_inference.sml

4Mutual recursion

fun f1 ... and f2 ... (and datatype t1 = ... and t2 = ...) lets bindings refer to each other; the other route is passing a function as an argument. [summary p.7]

fun even n = if n = 0 then true else odd (n - 1)
and odd n = if n = 0 then false else even (n - 1)
Try first: How would you write even/odd without and?

Define odd first taking a function argument: fun odd (f, n) = ... f (n-1), then fun even n = ... odd (even, n - 1).

Lecture code: 71_mutual_recursion.sml

Part II

Modules

Structures group bindings; signatures decide what outsiders can see.

5Structures for namespaces

structure M = struct bindings end groups bindings; outside, use M.name, or open M (best only for testing). [summary p.9]

structure MyMathLib = struct
  fun fact x = if x = 0 then 1 else x * fact (x - 1)
  val half_pi = Math.pi / 2.0
end
val pi = MyMathLib.half_pi + MyMathLib.half_pi

Lecture code: 72_namespace_mgmt.sml

6Signatures and hiding

A signature is a type for a module; structure M :> SIG makes anything not in SIG invisible outside, so you can change it freely. [summary p.9]

signature MATHLIB = sig
  val fact : int -> int
  val half_pi : real
end
structure MyMathLib :> MATHLIB = struct ... (* doubler hidden *) end

Lecture code: 73_signatures.sml

7Abstract types protect invariants

In a signature, type rational with no definition is abstract: clients can only use the module's functions, so they cannot build a value that breaks the invariant (e.g. denominator 0, not reduced). [summary p.11]

Cute twist: you may expose a constructor as a function, e.g. val Whole : int -> rational, without exposing the datatype itself.

signature RATIONAL_B = sig
  type rational                          (* abstract: constructors hidden *)
  exception BadFrac
  val make_frac : int * int -> rational
  val add : rational * rational -> rational
  val toString : rational -> string
end
Easy to get wrong: exposing the datatype

If the signature shows datatype rational = Whole of int | Frac of int*int, clients can write Frac (1, 0) and break every invariant.

Lecture code: 74_module_example.sml, 75_signatures_for_example.sml

8Signature matching rules

M :> S type-checks when every non-abstract type in S is in M, every abstract type in S is defined in M, every val in S has a type in M at least as general, and every exception in S is in M. [summary p.14]

Try first: Can a structure have extra bindings not in the signature?

Yes - they are just hidden. The reverse (signature names something the structure lacks) is an error.

9Equivalent implementations, different types

Two structures are equivalent if no client can tell them apart through the signature; and each structure's abstract type is distinct, so you cannot mix their values. [summary p.15]

(* Rat1.rational and Rat2.rational are different types, even with the same
   signature: Rat1.toString (Rat2.make_frac (1,2)) does not type-check. *)

Part III

Equivalence

When can you replace one piece of code with another?

10What equivalence means

Two functions are equivalent if, given the same argument, they have the same result, same (non-)termination, same visible mutation, same input/output and same exceptions. Avoiding side effects makes this far easier. [summary p.17]

fun f x = x + x                 (* equivalent to fun f x = 2 * x *)
fun g (f, x) = (f x) + (f x)    (* NOT equivalent to 2 * f x if f prints *)
Try first: Are fun f x = let val y = g x in y + y end and fun f x = g x + g x equivalent?

Only if g has no side effects (and terminates). Otherwise the second calls g twice.

11Standard equivalences

A few rewrites are always safe in ML; each one has a precondition you must check. [summary p.19]

RewriteSafe when
rename a variable consistentlynew name not already used in the body
use or remove a helper (val y = 2; fun f x = x + y)the helper's free variables mean the same where it is used
fn x => f x → fevaluating f has no effect (it is a variable/value)
let val x = e1 in e2 end → (fn x => e2) e1almost always: same steps, but only the let version lets x be polymorphic

12Revisiting the definition

Equivalence depends on the level you observe: PL equivalence ignores speed, but an asymptotic (big-O) view or a systems view (constant factors) may not. [summary p.21]

PL equivalence
same results and effects, any speed.
Asymptotic
same, and same big-O growth.
Systems
same, and comparable real-world speed.

13In short

  • ML infers types by collecting constraints in binding order; leftovers become 'a.
  • Value restriction: only values and variables get polymorphic val types.
  • and gives mutual recursion for functions and datatypes.
  • Signatures with abstract types let modules hide representation and protect invariants.
  • Equivalent = no client can observe a difference; no side effects makes it easier.
