Part I

Building new types

Three building blocks make every compound type.

1Each-of, one-of, self-reference

Every compound type is built from each-of (all parts present), one-of (exactly one variant) and self-reference (recursion). [summary p.1]

Building blockMeaningML example
Each-ofcontains t1 and t2tuples, records
One-ofcontains t1 or t2options, datatypes
Self-referencemay refer to itselflists, trees
Try first: Classify int list using the three blocks.

One-of (empty or cons) + each-of (cons has a head and a tail) + self-reference (the tail is an int list).

2Records and the truth about tuples

A record {name = "A", id = 7} accesses fields by name; a tuple is just syntactic sugar for a record with fields named 1, 2, ... [summary p.2]

val r = {name = "Ada", id = 41}     (* {id:int, name:string} *)
val n = #name r
val t = {2 = "hi", 1 = 3}            (* this IS (3, "hi") : int * string *)
Try first: When would you prefer a record over a tuple?

When there are many fields or fields of the same type: names prevent mixing up position 3 and 4. Tuples fit short, obvious pairs.

Lecture code: 21_records.sml, 22_tuples_as_syntactic_sugar.sml

3Datatype bindings

datatype t = C1 of t1 | C2 of t2 | C3 adds a new type t and constructors - functions that build a t and tag which variant it is. [summary p.3]

datatype mytype = TwoInts of int * int
                | Str of string
                | Pizza
(* TwoInts : int * int -> mytype,  Pizza : mytype *)
val a = Str "hi"

Lecture code: 23_datatype_bindings.sml, 25_useful_datatypes.sml

4Case expressions

case e of p1 => e1 | p2 => e2 checks the tag and binds the carried data in one step; a missing variant gives a warning; a branch that can never be used gives an error. [summary p.4]

fun f (x : mytype) =
    case x of
        Pizza => 3
      | Str s => 8
      | TwoInts (i1, i2) => i1 + i2
Easy to get wrong: why not isStr/getStr functions?

Case makes it impossible to forget a variant or read data from the wrong one; the compiler checks exhaustiveness.

Lecture code: 24_case_expressions.sml

5Recursive datatypes: expression trees

A datatype can refer to itself, which makes trees easy; functions over them recur once per recursive constructor field. [summary p.5]

datatype exp = Constant of int
             | Negate of exp
             | Add of exp * exp
             | Multiply of exp * exp

fun eval e =
    case e of
        Constant i => i
      | Negate e2 => ~ (eval e2)
      | Add (e1, e2) => eval e1 + eval e2
      | Multiply (e1, e2) => eval e1 * eval e2
Try first: Write number_of_adds : exp -> int.

Constant _ => 0, Negate e => number_of_adds e, Add(a,b) => 1 + both, Multiply(a,b) => both summed.

Lecture code: 28_another_expression_example.sml

6Type synonyms, lists and options as datatypes

type name = t only adds a new name, never a new type; lists and options are ordinary (polymorphic) datatypes you can case on. [summary p.7]

type card = suit * rank            (* card and suit*rank are interchangeable *)
fun sum xs = case xs of [] => 0 | x :: xs' => x + sum xs'
fun inc_or_zero o = case o of NONE => 0 | SOME i => i + 1

Lecture code: 27_type_synonyms.sml, 29_list_and_option_datatypes.sml, 30_polymorphic_datatypes.sml

Part II

Pattern matching everywhere

Patterns are not just for case: every val and fun binding uses one.

7Every function takes one argument

val (x, y, z) = e is a pattern match, and fun f (x, y, z) = e is one argument matched against a tuple pattern. [summary p.10]

fun full_name {first = x, middle = y, last = z} = x ^ " " ^ y ^ " " ^ z
fun rotate (x, y, z) = (y, z, x)
val t = (1, 2, 3)
val r = rotate t      (* passing one tuple value works *)

Lecture code: 31_eachof_pattern_matching.sml

8Type inference, polymorphism and equality types

Without type annotations ML infers the most general type; unconstrained types become 'a, and ''a means "any type that supports =". [summary p.11]

fun append (xs, ys) = case xs of [] => ys | x::xs' => x :: append (xs', ys)
(* 'a list * 'a list -> 'a list *)
fun same (x, y) = if x = y then "yes" else "no"
(* ''a * ''a -> string *)
Try first: Is 'a list * 'a list -> 'a list more general than string list * string list -> string list?

Yes: replace 'a with string consistently and you get the second, so the first can be used anywhere the second is needed.

Lecture code: 32_type_inference.sml, 33_polymorphic_and_equality_types.sml

9Nested patterns

Patterns nest to any depth, so one branch can check shape and bind deep parts at once; _ matches anything without binding. [summary p.13]

fun zip3 lists =
    case lists of
        ([], [], []) => []
      | (h1::t1, h2::t2, h3::t3) => (h1, h2, h3) :: zip3 (t1, t2, t3)
      | _ => raise BadTriple       (* needs: exception BadTriple *)

fun nondecreasing xs =
    case xs of
        [] => true
      | _ :: [] => true
      | h :: (n :: t) => h <= n andalso nondecreasing (n :: t)
Easy to get wrong: nesting case inside case

If you write case inside case to inspect parts, a nested pattern is usually clearer and lets the compiler check coverage.

Lecture code: 34_nested_patterns.sml, 35_more_nested_patterns.sml

10Function patterns: fun with multiple cases

fun f p1 = e1 | f p2 = e2 is sugar for fun f x = case x of p1 => e1 | p2 => e2. [summary p.15]

fun eval (Constant i) = i
  | eval (Negate e) = ~ (eval e)
  | eval (Add (a, b)) = eval a + eval b
  | eval (Multiply (a, b)) = eval a * eval b

Lecture code: 37_function_patterns.sml

Part III

Control and cost

Exceptions for errors; tail recursion for loops without stack growth.

11Exceptions

exception E of t declares, raise E v throws, e handle E x => e2 catches; exception values have type exn. [summary p.16]

exception MyUndesirableCondition
fun maxlist (xs, ex) =
    case xs of
        [] => raise ex
      | x :: [] => x
      | x :: xs' => Int.max (x, maxlist (xs', ex))

val w = maxlist ([], MyUndesirableCondition) handle MyUndesirableCondition => 42

Lecture code: 38_exceptions.sml

12Tail recursion and accumulators

A call is a tail call when the caller has nothing left to do after it; ML then reuses the stack frame, so it runs like a loop. [summary p.17]

Recipe: add a helper with an extra accumulator argument; the old base-case answer becomes the initial accumulator; the base case returns acc.

fun fact n =                       (* not tail: n * (...) waits *)
    if n = 0 then 1 else n * fact (n - 1)

fun fact2 n =                      (* tail recursive with accumulator *)
    let fun aux (n, acc) = if n = 0 then acc else aux (n - 1, acc * n)
    in aux (n, 1) end
Try first: Make sum : int list -> int tail recursive.

Hint: what does the base case return now?

fun sum xs = let fun aux (xs, acc) = case xs of [] => acc | x::xs' => aux (xs', x + acc) in aux (xs, 0) end

Lecture code: 39_tail_recursion.sml, 40_accumulators.sml

13Tail position, precisely

Tail position is defined recursively: the body of a fun is in tail position, and only some subexpressions inherit it. [summary p.19]

Expression in tail positionWhich parts stay in tail position
fun f x = ee
if e1 then e2 else e3e2, e3 (not e1)
case e of p => e1 | ...each branch (not e)
let ... in e ende (not the bindings)
f (e1) argumentnever the argument
Easy to get wrong: "tail recursion is always better"

Not for everything: on trees or when the natural version is clearer, plain recursion is fine. Use accumulators where a loop would be natural.

14In short

  • Compound types = each-of + one-of + self-reference.
  • Tuples are records with fields 1, 2, ...; every function takes one argument.
  • Datatype constructors build and tag; case checks the tag and extracts data, with exhaustiveness warnings.
  • Nested patterns replace nested case and hd/tl/null.
  • Tail calls need nothing after them; accumulators turn recursion into loops.
