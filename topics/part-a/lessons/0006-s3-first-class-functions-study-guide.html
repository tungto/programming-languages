Part I

Functions as arguments and results

Functions are values: pass them, return them, write them inline.

1First-class functions

A first-class function can be used anywhere a value can: passed, returned, stored in tuples and lists. A function that takes or returns a function is higher-order. [summary p.1]

fun n_times (f, n, x) =
    if n = 0 then x else f (n_times (f, n - 1, x))

fun double x = x + x
val x1 = n_times (double, 4, 7)      (* 112 *)
val x2 = n_times (tl, 2, [4,8,12])   (* [12] *)
Try first: What is the type of n_times?

('a -> 'a) * int * 'a -> 'a. It is polymorphic because nothing forces x to be an int.

Lecture code: 42_functions_intro.sml, 43_functions_as_arguments.sml, 44_types_and_functions.sml

2Anonymous functions and needless wrapping

fn x => e is a function with no name; but fn x => f x is just f, so write f. [summary p.4]

val x3 = n_times (fn x => x + x, 4, 7)
(* poor style *) n_times (fn y => tl y, 2, xs)
(* good style *) n_times (tl, 2, xs)
Easy to get wrong: fn for recursion

An anonymous function cannot call itself (it has no name). Use fun for recursive functions.

Lecture code: 45_anonymous_functions.sml, 46_unnecessary_function_wrapping.sml

3Map and filter

map applies a function to every element; filter keeps elements where a predicate is true. They are the two most-used higher-order functions. [summary p.5]

fun map (f, xs) = case xs of [] => [] | x::xs' => f x :: map (f, xs')
(* ('a -> 'b) * 'a list -> 'b list *)
fun filter (f, xs) =
    case xs of [] => []
             | x::xs' => if f x then x :: filter (f, xs') else filter (f, xs')
Try first: Using map and filter, get the squares of only the even numbers in xs.

map (fn x => x * x, filter (fn x => x mod 2 = 0, xs))

Part II

Lexical scope and closures

The single rule that explains what a function body can see.

4Lexical scope

A function body is evaluated in the environment where the function was defined, not where it is called. [summary p.6]

val x = 1
fun f y = x + y        (* captures x = 1 *)
val x = 2              (* shadows, does not affect f *)
val y = 3
val z = f (x + y)      (* f 5 = 1 + 5 = 6, not 7 *)
Try first: In the code above, what would z be under dynamic scope?

7 (x would be looked up at call time = 2). ML uses lexical scope, so 6.

Lecture code: 49_lexical_scope.sml, 50_lexical_scope_and_functions.sml

5Closures

A function value is a closure: the code plus the environment where it was defined. Calling it evaluates the code in that saved environment, extended with the argument. [summary p.7]

fun make_adder n = fn x => x + n    (* the closure remembers n *)
val add5 = make_adder 5
val r = add5 10                      (* 15 *)
Easy to get wrong: the closure copies the variable's future value

It stores the environment at definition time. With no mutation, that is the value then; it never sees later shadowing.

Try first: Why does lexical scope matter for filter: fun allGreater (xs, n) = filter (fn x => x > n, xs)?

The fn uses n from allGreater's environment. Inside filter, a different binding (even one named n) must not change the meaning. Lexical scope guarantees that.

6Why lexical scope

Lexical scope makes functions independent of the caller's variable names, lets you reason about them alone, and lets closures carry private data. [summary p.8]

Name independence
Renaming a local variable never changes what a function does.
Type-check at definition
The function's type depends only on where it is written.
Private data
Closures remember data no caller can reach.

Lecture code: 51_why_lexical_scope.sml

7Closures and recomputation

Code in the body of a fn runs each call; code in a let outside the fn runs once, so move expensive work outside. [summary p.9]

fun allShorterThan2 (xs, s) =
    let val i = String.size s            (* computed once *)
    in filter (fn x => String.size x < i, xs) end

Lecture code: 52_closures_and_recomputation.sml

8Fold

fold walks a list, combining each element into an accumulator; many list functions are one fold. [summary p.10]

fun fold (f, acc, xs) =
    case xs of [] => acc | x::xs' => fold (f, f (acc, x), xs')
val sum = fold (fn (acc, x) => acc + x, 0, [1,2,3])        (* 6 *)
fun count_in (xs, lo, hi) =
    fold (fn (acc, x) => if x >= lo andalso x <= hi then acc + 1 else acc, 0, xs)
Try first: Write all_positive with fold.

fold (fn (acc, x) => acc andalso x > 0, true, xs)

Lecture code: 53_fold_and_more_closures.sml

Part III

Closure idioms

Common patterns that closures make easy.

9Combining functions

f o g is composition: (f o g) x = f (g x). Pipelines read left to right with a custom |>. [summary p.11]

fun sqrt_of_abs i = (Math.sqrt o Real.fromInt o abs) i
infix |>
fun x |> f = f x
fun sqrt_of_abs2 i = i |> abs |> Real.fromInt |> Math.sqrt

Lecture code: 54_combining_functions.sml

10Currying and partial application

A curried function takes one argument and returns a function for the next; calling it with fewer arguments is partial application. [summary p.12]

fun sorted3 x y z = z >= y andalso y >= x     (* int -> int -> int -> bool *)
val t = sorted3 7 9 11
fun fold f acc xs = case xs of [] => acc | x::xs' => fold f (f (acc, x)) xs'
val sum = fold (fn (a, x) => a + x) 0          (* partial: int list -> int *)
val removeZeros = List.filter (fn x => x <> 0)
Easy to get wrong: the value restriction

val pairWithOne = List.map (fn x => (x, 1)) may give a warning and an unusable type. Fix: write it as a fun, or add a type annotation.

Try first: What is sorted3 7 9?

A function int -> bool that checks whether its argument is >= 9 (given 7 <= 9).

Lecture code: 55_currying.sml, 56_partial_application.sml, 57_currying_wrapup.sml

11Mutation with references

ref e makes a mutable cell; !r reads it; r := e writes it. Use sparingly: the binding r never changes, only the cell's contents. [summary p.15]

val x = ref 42
val y = x                     (* alias: same cell *)
val _ = x := 43
val w = !y + 1                (* 44 *)

Lecture code: 58_mutable_references.sml

12Callbacks

A library stores closures from clients and calls them on events; each closure carries its own private data, so the library needs no knowledge of their types. [summary p.15]

val cbs : (int -> unit) list ref = ref []
fun onKeyEvent f = cbs := f :: (!cbs)
fun onEvent i = List.app (fn f => f i) (!cbs)
val timesPressed = ref 0
val _ = onKeyEvent (fn _ => timesPressed := !timesPressed + 1)

Lecture code: 59_callbacks.sml

13Abstract data types with closures, and other languages

A record of closures that share hidden data acts like an object; languages without closures simulate them with objects (Java) or an explicit env pointer (C). [summary p.16]

LanguageHow the environment is carried
ML / JSclosure, automatic
Java (old)an object implementing an interface, fields = env
Cfunction pointer + void* env argument

14In short

  • Functions are values: pass them, return them, put them in data.
  • Lexical scope: a body uses the environment where it was defined.
  • A closure = code + defining environment.
  • map, filter, fold cover most list loops.
  • Currying gives partial application; watch the value restriction.
