Key words for datatypes and patterns

The words Section 2 uses for building and taking apart types, in plain English. Read before the study guide. It is a word list, not a lesson on how to write datatypes.

Source · section2sum.pdfTime · 25-35 minRecommended · the section summary, after this page

1How to use this page

Cover the meaning and say each word in your own words first. Then open the card. Each card has: a plain meaning, the smallest example, what it is not, and a picture to remember it.

Words in bold inside a meaning are the part to remember. Page links go to the exact page in the section summary.

Why words come first

The summary explains each idea using other key words. If one word is fuzzy, the whole sentence is fuzzy. Fixing the words fixes most of the confusion.

2Kinds of types

Section 2 starts by naming three ways to build any type.

Try first: say one sentence for each word before reading the cards

Base type, Compound type, Each-of (product) type, One-of (sum) type, Self-reference (recursive type), Record / field, By name vs by position, Syntactic sugar

Base type

A type that does not contain other types.

int   bool   unit   string

Not the same asCompound type: built from others.

summary p.1

Compound type

A type built from other types.

int * bool    int list    int option

summary p.1

Each-of (product) type

Holds all of its parts at once.

(1, true)     {name = "A", id = 1}

Not the same asResearchers say "product type".

Picture itA form with every field filled in.

summary p.1

One-of (sum) type

Holds exactly one of several options.

NONE or SOME 3

Not the same asResearchers say "sum type".

Picture itA menu: you pick one dish.

summary p.1

Self-reference (recursive type)

A type whose definition mentions itself, so it can describe lists and trees.

datatype exp = Constant of int | Add of exp * exp

summary p.1

Record / field

An each-of type where parts have names (fields). Order does not matter.

{first = "Ada", id = 7}    #first r

Not the same asTuple = by position.

summary p.2

By name vs by position

By name = find a part by its label. By position = find it by its place (1st, 2nd...).

#id r   (by name)    #2 t   (by position)

summary p.3

Syntactic sugar

A nicer way to write something the language already has. Removing it changes nothing about meaning.

(3, "hi")   is sugar for   {1 = 3, 2 = "hi"}

Not the same asNot a new feature.

Picture itA shortcut key: same action, less typing.

summary p.3

3Datatypes and case

These words describe your own one-of types.

Try first: say one sentence for each word before reading the cards

Datatype binding, Constructor, Variant, Carry, Case expression, Branch (arm), Pattern, Pattern matching, Exhaustive / inexhaustive, Type synonym, Infix

Datatype binding

A binding that makes a new type plus its constructors.

datatype mytype = TwoInts of int * int | Str of string | Pizza

Not the same asType synonym: only a new name, no new type.

summary p.3

Constructor

A tag that builds a value of a datatype and remembers which variant it is. It is a function if it carries data, a value if not.

TwoInts : int * int -> mytype     Pizza : mytype

Not the same asNot a Java class constructor; also used in patterns.

Picture itA labelled envelope: the label says what is inside.

summary p.4

Variant

One of the options of a one-of type.

Str "hi"   is the Str variant

summary p.4

Carry

What data a constructor holds. "Str carries a string".

Str of string

summary p.4

Case expression

Look at a value, pick the first branch whose pattern matches, and run that branch.

case x of Pizza => 3 | Str s => String.size s | TwoInts (a, b) => a + b

Not the same asLike if-then-else, but with many branches.

summary p.4

Branch (arm)

One p => e part of a case.

Pizza => 3

summary p.5

Pattern

A shape that a value is checked against; it can bind names to pieces. It looks like an expression but is not one.

TwoInts (a, b)     x :: xs'     (x, y, z)     _

Not the same asNot an expression: it is never evaluated.

Picture itA cookie cutter.

summary p.5

Pattern matching

(1) Does the value fit the pattern? (2) If yes, bind the variables to the matching pieces.

summary p.13

Exhaustive / inexhaustive

Exhaustive = every variant has a branch. Missing one gives a warning and maybe an exception at run time.

Not the same asRedundant branch (can never run) = an error.

summary p.5

Type synonym

type name = t: a second name for an existing type. Fully interchangeable.

type card = suit * rank

Not the same asDatatype creates a truly new type.

Picture itA nickname.

summary p.7

Infix

Written between its two operands.

1 :: xs     a + b

Not the same asPrefix: f x.

summary p.9

4Polymorphism and patterns everywhere

Words that explain the strange types the REPL prints.

Try first: say one sentence for each word before reading the cards

Polymorphic, Type variable ('a), More general type, Equality type (''a), Type inference, Wildcard (_), Nested pattern, Unit / ()

Polymorphic

Works for many types.

fun len xs = ...   : 'a list -> int

Picture itOne key that fits many locks.

summary p.9

Type variable ('a)

A placeholder meaning any type. Say "alpha". Each 'a in one type must be the same type.

'a list * 'a list -> 'a list

summary p.12

More general type

A type you can turn into another by replacing type variables consistently. More general is fine for homework.

'a list -> int   is more general than   string list -> int

summary p.12

Equality type (''a)

Two apostrophes: any type that supports =. Not functions, not real.

fun same (x, y) = if x = y then "yes" else "no"   (* ''a * ''a -> string *)

summary p.12

Type inference

The compiler works out types you did not write. Every value still has a type.

fun sum_triple (x, y, z) = x + y + z   (* int * int * int -> int *)

Not the same asNot dynamic typing.

summary p.11

Wildcard (_)

A pattern that matches anything and binds nothing.

_ :: xs' => 1 + len xs'

Not the same asVariable pattern: also matches anything, but binds a name.

summary p.14

Nested pattern

A pattern inside another pattern.

(a, b, c) :: rest     h :: (n :: t)

summary p.13

Unit / ()

The type with one value, (). Means "nothing interesting".

fun f () = 3

Not the same asNot NONE.

summary p.11

5Exceptions and the call stack

Words for errors and for why tail recursion is fast.

Try first: say one sentence for each word before reading the cards

Raise / handle, exn, Call stack / stack frame, Tail call, Tail position, Accumulator, Associative, Linear / quadratic

Raise / handle

Raise = throw an exception. Handle = catch it and give another answer.

maxlist ([], E) handle E => 0

summary p.16

exn

The type of exception values.

exception MyErr of int * int     (* MyErr : int * int -> exn *)

summary p.17

Call stack / stack frame

A stack with one frame per function call that has started but not finished. The frame stores what is left to do.

Picture itA pile of sticky notes: each says "come back and finish this".

summary p.18

Tail call

A call where the caller has nothing left to do after it returns. ML reuses the frame.

aux (n - 1, acc * n)   (* tail call *)
n * fact (n - 1)      (* NOT a tail call: * waits *)

summary p.18

Tail position

The places in code where a call would be a tail call (body, branches of if/case, body of let; never an argument).

summary p.19

Accumulator

An extra argument that carries the answer so far.

fun aux (xs, acc) = case xs of [] => acc | x :: xs' => aux (xs', x + acc)

Picture itA running total on a receipt.

summary p.18

Associative

Grouping does not matter: a * (b * c) = (a * b) * c. Needed when switching to an accumulator.

summary p.19

Linear / quadratic

Work grows like n / like n². rev1 with @ is quadratic; with an accumulator it is linear.

summary p.19

6One value, matched step by step

Pattern matching does two jobs at once: check the shape, then bind the pieces. Follow one value through a case.

CodeWhat changesWhy
value: TwoInts (7, 9)try Pizzano match, next branch
try Str sno match, next branch
try TwoInts (i1, i2)match: bind i1 → 7, i2 → 9
evaluate i1 + i2result 16; other branches never run
Try first: Does a :: (b :: (c :: [])) match a 4-element list?

No. It matches lists with exactly three elements. a :: b :: c :: d matches three or more.

Try first: Is fun f (x, y) = x + y a two-argument function?

No. It is one argument (a pair) matched with the pattern (x, y).
